# Phase 20A — authenticated Cloud MCP metadata (2026-11-24)

Rust beta implements stateless JSON-RPC over HTTP at POST /mcp, with OAuth protected-resource discovery and bearer challenges. GET /mcp is not an SSE stream and returns 405 for an authenticated request. Every request validates the token hash, audience, expiration and account security version against PostgreSQL, and applies Redis throttles. Browser Origin must match the explicitly configured beta origin if supplied. Only initialize, ping, tools/list, and workspace(action=list) are supported. Notifications never execute tools.

The workspace list returns only currently registered non-system, non-managed workspace metadata for the token's account, with real Redis presence. It never returns local paths, credential IDs, keys, or secrets. No filesystem, terminal, edits, remote runtime dispatch or approval bypass is available. Unknown tools/actions are rejected. No session-based MCP streaming, refresh token rotation, MCP usage event producer or full compact-tool parity is claimed.

Local 94 Rust tests pass and Clippy is clean. The existing real-store integration test now checks an issued access token can initialize/list tools/list empty account workspace metadata; invalid, expired, security-version-mismatched and revoked tokens are rejected, as are unsupported tools. CI on the pushed commit is required for real-store acceptance. The live workspace listing, multi-account integration, proxy/Next.js routing and actual MCP client compatibility require further integration testing. Main, archived Go and production are unchanged.
